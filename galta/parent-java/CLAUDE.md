# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`parent-java` holds the Galta modules for the Java language. The pom only aggregates them.

## Sub-modules

| Module | Artifact | Purpose |
|---|---|---|
| `playground-java-cheerpj` | `playground-java-cheerpj` | The browser (CheerpJ) build: shaded `target/javaplayground-cheerpj.jar`, entry point `playground.JavaPlaygroundCheerpJ`; not published, `buildtools/build-site.sh` copies the jar to `docs/java-playground/` |
| `playground-java` | `playground-java` | The Java playground: `Main.java` (compiled in memory by `javacompiler`) and `Main.jshell` (JShell) snippets; entry point `playground.JavaPlayground`. Moved from Galta-Java-Private (`playground-java-incubator`) |

Test suite: `AllLangJavaTests`, which also runs every packaged snippet (`PackagedSnippetsTest`), the JShell ones twice: with JShell, and converted to a class (`-Dplayground.jshell.convert=true` path, what runs without JShell): both must print the same. A Galta API change that breaks a snippet fails the build.

Without JShell (CheerpJ), `JShellExecutionEngine` converts the script with `JShellScriptConverter`: top-level variables become locals of `main()`, so a lambda can't declare a parameter named like one (JShell allows it). `playground-java-cheerpj` bundles the Eclipse compiler (ecj), used by `javacompiler` when `jdk.compiler` is missing, and its tests run with `--limit-modules java.se` (`CheerpJSnippetsTest`): the browser setup, checked on every build. The snippets' `resources.manifest` is regenerated by the build (`filesystem-resources-manifest` plugin) and is checked in.

The playground itself (snippet tree, editors, scratchpad, execution controller) is in `parent-playground`; the scratchpad of this playground is `Main.jshell` (`getMainFileName()` of its engine factory).
